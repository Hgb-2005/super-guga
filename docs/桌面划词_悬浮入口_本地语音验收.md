# 咕嘎录音、全局划词与悬浮入口验收

更新：2026-11-10。当前版本：`2026-11-10.unified-record-send.2`。

## 当前交互

已经合并录音入口，不再提供单独的「本地听说」按钮或自动连续收音模式。原来的本地识别与 Edge TTS 保留，统一接到现有「点击说话」。

1. 点击气泡里的「点击说话」、录音条空白处或右侧 ↑，开始录音。聊天窗口的「说话」使用同一个录音组件。
2. 开始后显示录音时长与真实收音音量，右侧 ↑ 表示发送，左侧 × 表示取消。松开鼠标不会结束录音，停顿不会自动发送。
3. 点 ↑ 后才识别并提交这段话；咕嘎沿用现有问答、每日计划和任务执行能力，以 Edge TTS 朗读回答。准备或识别期间禁止重复发送。
4. 点 × 丢弃录音，不提交给问答或任务模型。录音达到 30 秒会停止收音并保留草稿，仍需点击 ↑ 才发送。
5. 实时语音继续单独保留。普通录音不连接实时语音模型、不消耗实时语音额度；普通文字问答、看图和复杂任务仍使用已配置的对应模型。

## 全局划词

咕嘎启动后默认启用监听。在网页、文档等可读取文字选区的软件中，左键拖选或双击选词即显示「截图提问 / 解释」，不需要再点右键。

工具条是独立的桌面置顶窗口，高于网页里的划词浮层，不抢键盘焦点，也不模拟复制或改动剪贴板。读取优先从鼠标所在文字控件及其文档向上查找，避免网页自己的浮层改变焦点后丢失选区。确认真实选中文字后才显示，不把图片或空白拖选当成文字。

「解释」优先使用原文和段落；「截图提问」使用缓存的局部画面。截图暂不可用时，文字解释仍能使用，截图提问可重新框选。这些功能不要求开启实时语音或连续屏幕采集。某个软件不开放文字选区时，使用菜单中的框选识字或截图提问。

隐藏桌宠后仍保留悬浮入口，点击可打开原对话，菜单可使用录音、截图、每日计划和恢复桌宠。后台任务不会因为隐藏而取消。

## 你来验收（约 5 分钟）

| 项目 | 操作 | 通过标准 |
|---|---|---|
| 点击即录音 | 点现有录音条的「点击说话」后松开鼠标 | 显示录音中、时长和音量；无需长按，不启动另一种听说模式 |
| 发送 | 说「打开浏览器」，停顿两秒，再点右侧 ↑ | 停顿期间不执行；点 ↑ 后才执行并语音回复 |
| 取消 | 录入一句话后点 × | 不发送文字、不执行任务，恢复「点击说话」 |
| 满时长 | 不点发送，录音到 30 秒 | 停止录音，保留草稿，等待 ↑ 或 × |
| 聊天框入口 | 打开完整对话，点「说话」 | 出现同样的录音条，没有单独「本地听说」按钮 |
| 网页划词 | 在平时使用的网页左键选一段字，包括带网页自有划词浮层的页面 | 不需右键，出现咕嘎「截图提问 / 解释」，显示在网页浮层上方 |
| 独立解释 | 不开语音，选词后点「解释」，继续追问 | 回答针对实际选词，不开启长语音或连续共享屏幕 |
| 隐藏恢复 | 隐藏桌宠后点击悬浮入口，再从菜单恢复 | 原对话仍在，录音入口可用，后台任务保留 |
