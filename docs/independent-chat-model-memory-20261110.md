# 咕嘎独立文字问答与记忆修复

版本：2026-11-10.independent-chat-memory.4。

普通聊天由咕嘎直接请求配置中的 DeepSeek 模型，不启动 DSH 任务，不经过 DSH 网关，不要求打开 DSH 界面。“复用本机 DSH 模型配置”仅读取本机已保存的模型地址、模型名和密钥引用；密钥不显示在诊断里，也不复制到咕嘎配置。

## 本次修改

- 桌宠旁普通文字输入改为进入统一陪伴聊天，避免落到早期战棋人设和独立历史。战棋专用入口保留。
- 普通问答系统提示词明确优先大白话、生活例子、必要术语随口解释，维持管家与陪伴定位。
- 保留用户、项目、当前对话分层记忆及实时每日计划，并在问答工作线程只读召回灵枢资料。灵枢结果仅作共享历史资料，不能覆盖本轮更正、用户分层记忆或实时计划，也不能当作当前任务进度。
- 灵枢查询按具体问题缓存，最多 32 条，不将其他问题的缓存当作本轮结果；只向主咕嘎注入，不把共享记录当成其他成员的私人记忆。凭据内容过滤；不自动写入测试记忆。
- 本轮召回最多等待 5 秒，召回故障或超时不阻断模型回答；启动与读取各有上限。复用咕嘎自己管理的灵枢读取进程，退出时关闭。
- 普通闲聊和稳定概念解释不再一律搜索；明确联网或时效问题保留搜索。普通问答不再无故加“本轮联网未能核实”。
- 聊天作为独立顶层窗口，隐藏桌宠后仍可展开。管理台来源说明补充“无需打开 DSH”。
- app_state.model_answer 显示最近问答的模型、是否带本地记忆、灵枢读取状态/数量、成功正文长度与搜索状态，不含密钥和记忆正文。

## 已验证

81 项相关测试通过，覆盖普通输入分流、系统提示词和分层记忆/灵枢共同入参、记忆超时与失败降级、查询缓存隔离，以及原有聊天与手动语音回归。

真实 AnswerWorker 请求已成功：deepseek-v4.1-flash 返回 132 字生活比喻；带本地分层记忆及 4 条灵枢资料；search_state=not_needed；约 6 秒；没有使用 DSH 任务、麦克风或朗读。报告：runtime/independent-chat-qa/real-driver-answer.json。测试没有关闭用户自己的 DSH 窗口；“无需 DSH”依据咕嘎直接 HTTP 请求链路及未调用 DSH 任务，并不声称做过关闭窗口的验收。

完整聊天窗口链路另已通过真实模型验证：在隔离 Qt 窗口和临时记忆中保存喜欢生活例子的偏好，调用 send，再接收实际 DS 回答、写入记录并核对界面正文。实际回答将缓存比喻为做饭时把盐、酱油摆在灶台边，79 字，约 5.5 秒；灵枢读取 4 条，共享工作记忆是实际服务。报告：runtime/independent-chat-qa/real-chat-window.json。隔离运行不使用真实用户麦克风或朗读，也不把测试偏好写进用户记忆。当前桌面实例的新代码加载已核对；真机自动点击验收因 Windows 控制工具无法绑定该聊天窗口未完成。

## 用户验收

1. 不打开 DSH，在咕嘎聊天输入“用大白话和一个生活例子解释一下大模型是什么”。应出现完整文字正文，不要求先启动 DSH，不应出现无关联的联网失败提示。
2. 输入“记住：我喜欢用生活里的例子解释问题”，换一个咕嘎对话，再问“按我喜欢的方式解释一下什么是缓存”。应使用生活例子。只保存你明确提供的偏好。
3. 针对灵枢里确实存在的一项旧工作结论提问；应结合相关历史，缺少资料时据实说明。诊断 lingshu_state=ok 仅表示读到记录，回答是否准确使用仍需核对正文；无相关记录不能声称记得。
4. 隐藏桌宠后，从悬浮入口展开对话，继续发文字，仍应展示回答。

不把接口成功等同于麦克风、扬声器或全局划词通过；这些另行验收。本次保留原有未提交代码、真实历史和计划，未安装新组件。
