# 差最后一步发不出去：根因与修复（2026-11-08）

## 现象

截图显示：微信已打开、已进入"小军"会话、输入框里已填好"最近还忙吗？"，
但消息没有发出去。企鹅自述"卡在我找联系人这一步了"，与实际进度不符。

任务记录 `runtime/agent-tasks/9699ecec553942c1bdc32aec4c07e34d.json`：

- 20 次工具调用，15 次成功，最后状态 paused
- `last_tool_failure`：`computer` / `press` / `未知屏幕操作`
- 契约失败项：`wechat 未获得成功验证回执，不能声称已完成`

## 三条根因

### 1. 工具不认"按一下"这个动作

模型自然地调用 `computer(action='press', keys='enter')` 想按回车发送。
但 `computer` 的支持动作里根本没有 `press`，也没有任何"按键"语义能兜住它，
于是直接抛 `未知屏幕操作`。消息因此永远停在输入框里。

### 2. 错误只说"未知"，不说"支持什么"

原错误是四个字：`未知屏幕操作`。模型不知道是动作名错了、参数错了还是目标错了，
只能自己编一个解释——这就是它说"卡在找联系人"的来源。

另外动作名的校验排在"观察 ID 是否过期"之后，动作写错时先收到的是
"观察 ID 已过期"，更容易误导。

### 3. 微信专用工具在本机用不了

`core/wechat_demo.py` 依赖 Windows 自带 OCR 识别"搜索"和"发送"两个词来定位控件。
这台机器未安装中文识别语言包，所以 `wechat` 工具一上手就失败（任务里连续两次 ok=false），
模型只能退回手动截图点击，走到最后一步撞上第 1 条。

## 修复

1. `computer` 新增 `press` 动作，接 `keys` / `key` / `text` 三种字段写法，缺省为回车；
   中文的"回车/发送/确认/提交"都映射到 enter。按键不再要求观察 ID（它没有坐标）。
2. `computer` 的 action 白名单前置校验：动作名不认识时立刻报错，并列出全部支持的动作，
   不再被"观察 ID 过期"抢先。
3. `wechat` 工具在缺少 OCR 组件时，错误信息直接给出可执行的手动路径
   （observe → click 搜索框 → type 名字 → click 联系人 → type 正文 → press enter → observe 核对）。
4. `agent_failure` 对"未知屏幕操作"给出针对性下一步：不是找不到目标，而是动作名不受支持。

## 验证

- 新增 `tools/test_press_action.py`（9 项）：按键别名、组合键、无需观察 ID、
  字段兼容、无前台窗口拒绝、未知动作列出支持项。
- 116 项回归全通过（按键、智能体参数、窗口指令、按需视觉、语音队列、浏览器响应等）。
