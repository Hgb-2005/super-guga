# 咕嘎管家与陪伴记忆（2026-11-10）

## 定位与范围

咕嘎是保留小企鹅个性的管家与陪伴型智能体。核心是理解用户、管理日常安排、关心感受，以及按需处理生活和电脑事务。代码修改是用户提出需要时调用的能力。

此次复用原有聊天窗口、SQLite、桌面工具和 DSH，不安装 Pi、不另建聊天入口、不改变 DSH 的执行方式。现有未提交工作保留。本次新增的数据库字段均为追加迁移，历史聊天不删除，也不根据猜测分配给某个新对话。

## 聊天里直接表达

```text
我的每日计划是：早上八点学习英语；晚上跑步半小时
我每天要：学习；运动；睡前阅读
你还记得我的每日计划吗
每日计划 完成 学习
每日计划 把 学习 改成 阅读
每日计划 删除 运动
```

前两种明确的每日安排直接写入持久计划，换对话、重启仍可用。已有事项和打卡保留；不会因为重新发一遍而重复添加或自动标记完成。聊天会读取全部有效的长期安排和今天的真实打卡，即使今天没有重复事项，也知道周内其他日期的安排。原有计划窗口作为查看和管理入口保留，使用时无需先进入设置。

问句、假设、引用、明确要求不保存的信息、凭据与只有今天/明天的一次性安排不自动转成每日习惯。每周重复、复杂修改等表达交给具备 daily_plan 工具的现有智能体理解；不会猜成每天重复。复杂自然语言路径仍依赖可用的模型服务。

## 记忆层级

| 层级 | 使用范围 | 行为 |
| --- | --- | --- |
| 用户长期信息 | 同一成员的不同对话 | 用户明确表达的喜好、职业、称呼和交流语言等；稳定字段的更正替换旧值 |
| 项目记忆 | 同一项目的对话 | 项目事实、约定与背景，不进入其他项目 |
| 对话记忆 | 当前对话 | 临时背景，不跨对话注入 |
| 日常安排与打卡 | 同一桌宠共享 | 以 daily-plan.sqlite3 为唯一来源；不复制到普通事实表，防止改计划后仍召回旧清单 |

成员之间原有私人记忆隔离保留。未指定对话来源的旧聊天不参与新的对话召回。主动聊天只读取当前对话原文和当前可见的分层事实。所有召回事实带记录日期；“今天/明天”按记录日期解释。当前项目和对话记忆需要明确存储范围，不能声称已自动总结所有历史项目。

本地管理示例：

```text
记住：我喜欢简洁的报告
记住：这个项目：主题是海边旅行
记住：本对话：今天有点紧张
查看我的记忆
忘记记忆 真实编号
```

本地执行智能体和 DSH 共用 CompanionMemory 服务与 personal_memory 工具，可查询、保存、更正、遗忘。工具默认保存到当前对话，稳定用户信息才选 user；项目事实选 project。DSH 使用启动任务时绑定的对话范围，不借用用户后来切换到的对话。

## Pi 判断

Pi 官方将其定义为可扩展的 agent harness，提供 TypeScript SDK 和可供其他语言接入的 RPC：

- https://github.com/earendil-works/pi/blob/main/packages/coding-agent/README.md
- https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md

基于这些接口，可以将 Pi 作为未来的一种可选执行器。它不会自动提供咕嘎所需的用户画像、日常安排、陪伴人格与记忆隔离。本次判断是先完善咕嘎自己的管家记忆，复用现有执行能力；若未来接入 Pi，外壳、记忆、语音与任务协调仍归咕嘎，DSH 继续作为可调用执行器。此次没有完成 Pi 接入，也没有新建代码智能体产品。

## 验证与生效边界

使用独立临时数据库和隔离 Qt 窗口验证自然语言保存、跨对话注入、重启持久化、项目/成员隔离、来源隔离、更正遗忘、凭据过滤、批量原子性、跨日重置、DSH 工具共用与已有聊天/语音/任务回归。模型调用在测试中截获，没有将临时资料送给外部模型。真实麦克风、物理扬声器与远程模型语义理解不属于此次通过的验收。

132 项相关自动化测试通过。入口：tools/test_companion_memory.py、tools/test_companion_chat.py。现有 MCP 握手测试的工具清单同步到已经存在的每日计划和桌面工具。

代码版本：2026-11-10.companion-memory.1。运行中的 Python 进程需要重新加载代码后生效；此次开发验收不等同于当前桌面常驻进程已加载，也不等同于安装包已重新构建。本次检查发现单实例标记存在，但当前项目默认 MCP 接口连接失败，因而没有强制结束无法核对通话/任务状态的常驻实例。
