# 咕嘎与本地 DSH 真机验收方案

本方案由你操作真实界面、麦克风和扬声器。当前代码已做隔离测试，不能用隔离结果代替下面的真机通过。

## 0. 准备（约 2 分钟）

1. 先保存 DSH 当前工作，关闭并重新打开**你电脑原来的 DeepSeek Harness 图标**。它是 `G:\Doubao\智能体\dsh\launcher\launcher.py` 启动的 UI。
2. 退出咕嘎后，重新启动本项目的 `启动企鹅.bat`。旧进程不会自动加载新 Python 代码。
3. DSH 保持你平时使用的模型和凭据。新增插件不会替换模型。咕嘎语音模型的凭据单独配置；看到 401 时先解决凭据，不能判定为桌面插件故障。
4. 先用文字做测试 1—5，再打开长语音做测试 6—8。不要选真实联系人或执行实际发送。

## 1. 插件在本地 UI 可见

打开 DSH 的设置 → 插件，查找 **咕嘎 · 桌面助手**（包名 `dsh-guga-desktop`，版本 `0.1.0`）。

通过标准：已安装、已启用，说明包含桌面操作、每日计划和任务进度；没有重复的旧 `guga-desktop-mcp` 配置。
只有通用 MCP 客户端而没有咕嘎名字，不算这一项通过。

## 2. DSH → 咕嘎：读计划和气泡

先在咕嘎聊天框输入：

```text
每日计划 添加 验收_读书
每日计划 完成 验收_读书
```

再在 DSH **新建一个验收会话 A**，输入：

```text
这是咕嘎插件验收。请调用 mcp__guga__daily_plan(action=list)，告诉我今天已勾选哪些事项。
然后调用 mcp__guga__pet_say，在咕嘎气泡显示“DSH 已读到你的真实每日计划”。
不要修改其他计划，不要发微信，不要用你自己的文字回答代替工具调用。
```

通过标准：DSH 执行记录里出现真实插件调用；回答包含 `验收_读书` 已勾选；桌面咕嘎显示指定气泡。
模型只说“我会调用”而没有记录和气泡，判失败。

## 3. DSH → 咕嘎：打开浏览器

在同一 DSH 会话输入：

```text
请使用咕嘎插件 mcp__guga__applications(action=open, name=浏览器) 打开或聚焦我的默认浏览器。
只做这一步，不搜索、不登录、不操作其他网页。以工具回执说明是否实际确认到窗口。
```

通过标准：电脑默认浏览器真的出现或从后台被聚焦；DSH 有 `mcp__guga__applications` 回执。
不确定、权限不足或没有窗口时应如实报错，不得自动重复打开。

## 4. DSH → 咕嘎：任务进度定期回传

在 DSH 会话 A 输入：

```text
做一个约 70 秒的隔离联动验收，不访问网络、不修改项目、不发消息。
在系统临时目录新建一个独立验收目录，分三次往 progress.txt 追加“阶段1/阶段2/阶段3”；每次间隔约20秒。
执行结束后回读文件，给出三行是否齐全和文件的实际路径。让咕嘎原生插件根据宿主事件汇报，不要自己伪造进度百分比。
```

通过标准：咕嘎能够在任务中每约 30 秒给出真实阶段/工具状态，任务结束后收到“本轮结束”和 DSH 的公开答复。
连续没有新结果时只能说仍在处理，不能编造“80%”。网络或模型失败也应传回失败，不能说任务已完成。

在咕嘎聊天框输入 `查看DSH进度`：目标、会话编号、状态应与 DSH 一致。

## 5. 两个会话与停止任务

1. 新建 DSH 会话 B，输入另一项简单任务，例如“只通过咕嘎插件读取每日计划，不改计划”。
2. 在咕嘎输入 `查看DSH进度`，应能分清 A、B，不能把 A 的结果说成 B 的结果。
3. 需要回到 A 时，在咕嘎输入 `关注DSH会话 实际会话编号`（编号来自查询结果，不能猜）。
4. 在 DSH 发起一个等待任务，然后**在 DSH 内点击停止**；咕嘎应收到取消/结束状态，不继续声称仍在执行。

当前焦点依据是“最近发起任务的主会话”，也支持显式关注；只切换 UI 页签但没有发新消息，不会自动改变关注。
当前没有实现从咕嘎取消、暂停或恢复外部 DSH 会话；这些操作请在 DSH 内进行。不能把这一项误当成已经双向接管。

## 6. 长语音基本能力（约 5 分钟）

打开咕嘎长语音，依次说：

```text
你好，记住本次对话的口令是蓝色企鹅。
你现在能看见什么？
打开浏览器。
刚才的口令是什么？
```

然后让它解释一个稍长的问题，途中说“先停一下，回答我的新问题”。

通过标准：正常收音、可听回复、屏幕事实准确、浏览器命令正常、记得本次口令、打断后不继续念旧回答。
保持同一连接继续说话，不能因为节省用量而缩短通话、漏掉一句话或丢失尚在进行的任务。

## 7. 语音汇报 DSH 且不抢话

长语音保持开启，重复测试 4。任务中与咕嘎说一句普通话，再问“DSH 现在在做什么”。

通过标准：任务照常继续；咕嘎按实际状态回答；定期汇报不打断你正在说话，也不与已有播音重叠。
关闭 DSH 后，咕嘎应在心跳过期后的下一次汇报提示“进度连接中断，不能判断任务是否结束”，不能说成功。

## 8. 用量验收（建议 10—15 分钟）

固定同一语音模型、声音、设备和碎碎念频率。做一段连续对话，包含看屏幕、打开软件、打断和 DSH 进度汇报。

结束后运行项目里的 `查看语音用量.cmd`，查看：

- 真实回复轮数、已上报轮数和未上报轮数。
- 输入文本、输入音频、输出文本、输出音频 token，以及服务端提供时的缓存计数。
- 汇总文件 `runtime/native-dsh-voice-qa/voice-usage-summary.json`；逐轮原始数字在 `runtime/voice/usage-日期-进程号.jsonl`。

未上报必须显示“未知”，不能当作免费或零消耗。日志里不能出现录音、转写正文、密钥或完整提示词。

这次优化去掉了同一连接中反复传入的旧对话文本；**没有把 67.5% 的指令数据减少量当成实际 token/费用节省率**。
服务端仍可能计入语音上下文。没有可比的真实旧账单时，费用降幅一栏写“待验证”。
